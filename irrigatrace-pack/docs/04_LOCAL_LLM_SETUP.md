# 04 — Local LLM Setup (Ollama) — and how to use it safely

## Decision
- Runtime: **Ollama**.
- Primary model: **`qwen3:4b`** (check `ollama list` first — if a Qwen 4B is already installed from another project, reuse it and skip the download).
- Embeddings: **`nomic-embed-text`** (768-d).
- Before pulling, the agent must check hardware and pick a tier:

| Machine | Model | Notes |
|---|---|---|
| ≤ 8 GB RAM, no GPU | `qwen3:1.7b` | Template fallback will carry more load |
| 8–16 GB RAM or 4–6 GB VRAM | **`qwen3:4b`** (default) | Best quality/size for JSON-constrained narration |
| ≥ 16 GB RAM or ≥ 8 GB VRAM | `qwen3:8b` | Optional upgrade; only if latency stays < 6 s per narration |

If a newer Qwen/Gemma generation exists on ollama.com/library at build time with a ~4B instruct variant, the agent may swap it in **only** after passing the narration eval in this doc (section "Acceptance"). Record the choice in `docs/ASSUMPTIONS.md`.

## Download in the background (agent must not wait)
```bash
# macOS/Linux
scripts/pull_models.sh qwen3:4b nomic-embed-text
# Windows PowerShell
.\scripts\pull_models.ps1 qwen3:4b nomic-embed-text
# readiness (any time)
python scripts/check_models.py
```
Then **immediately continue with other tracks**. Logs: `.logs/pull-*.log`. When `check_models.py` shows both `true`, run `make llm-eval`. Never poll in a tight loop; check at natural task boundaries.

## What the LLM is allowed to do
| Job | Input | Output | Constraint |
|---|---|---|---|
| **Narrate** a decision | Deterministic explanation JSON (factors, thresholds, fired rules, action, duration) | 2–3 plain-English sentences | Every number in output must appear in input |
| **Summarize a comparison** | Comparison JSON (deltas + flip analysis) | 2–3 sentences, observed differences only | No causal verbs unless backed by a flip result |
| **Parse a query** (⌘K) | User text + filter schema | JSON filter object | Backend validates against schema; never raw SQL |
| **Embed** | Decision/reason text | vector | via `nomic-embed-text` |

The LLM **never** produces action, duration, confidence, or edits a record.

## Ollama call contract
- Endpoint `POST {OLLAMA_HOST}/api/chat`, `stream:false`, `options: {temperature: 0.2, seed: 42, num_ctx: 4096}`.
- Disable "thinking" for narration (`think:false`, or `/no_think` fallback) to keep latency low and output clean.
- Use structured output: pass a JSON Schema in `format`. Narration schema: `{ "narrative": string, "key_points": string[≤3] }`.
- Timeout 20 s, 1 retry, then fallback.

## Number-consistency validator (mandatory)
```
numbers_in(text)  ⊆  numbers_in(evidence_json) ∪ {allowed_unit_words}
```
- Extract numerals (incl. decimals, percents), normalize (`2.8`, `2.8 hours`, `2.8 h`).
- Reject if the text contains a number absent from evidence, or contradicts the action (e.g. says "wait" when action = IRRIGATE).
- On reject: retry once with "Use only these numbers: …" appended; then fall back to the deterministic template.
- Always store provenance: `{source: "ollama|gemini|template", model, model_digest, prompt_sha256, temperature, seed, validated: bool, created_at}`.

## Prompt templates (store in `api/irrigatrace/services/prompts/`)
**narrate_decision.system**
```
You explain irrigation recommendations to farm supervisors. You are given a JSON record produced by a rule engine.
Rules: use ONLY facts and numbers present in the JSON. Do not add advice, causes or numbers. Do not change the action or duration.
Write 2-3 short sentences in plain English. Mention the action, the duration if any, and the main factors in the order given.
Return JSON: {"narrative": string, "key_points": string[]}.
```
**summarize_comparison.system**
```
You describe differences between two irrigation decisions for the same plot. You are given JSON with input deltas, output deltas, fired-rule changes and flip analysis.
State what changed. You may say an input "alone flips the action" ONLY if flip_analysis says so. Otherwise say the changes "coincided with" the new recommendation.
Use only numbers from the JSON. 2-3 sentences. Return JSON: {"summary": string}.
```
**parse_query.system**
```
Convert the user's request into a JSON filter using ONLY these fields: plot_code, status[], overridden(bool), ruleset_version, date_from, date_to, action[], text_query. Unknown fields are forbidden. If the request cannot be expressed, return {"error":"unsupported"}.
```

## Acceptance (`make llm-eval`)
Run 20 seeded decisions through narrate: **≥ 95% pass the validator on first or second attempt**, median latency < 6 s on the dev machine, zero action/duration contradictions. Print a table. If below threshold: lower tier model, tighten prompt, or rely on template — never loosen the validator.

## UI treatment
Narrative shown in a card labeled **"Plain-English summary · generated by local model qwen3:4b · verified against engine record"** (or **"Template summary"** when fallback). The authoritative deterministic factor list is always shown beside it.
